01演算法在研究什麼？好問題與難問題

Chapter 1 · Introduction

Algorithm 就是「解決問題的步驟描述」，例如起床 → 刷牙洗臉 → 吃早餐 → 穿衣 → 搭車。 同一個問題可以有很多種演算法（例如排序可以用 insertion、quick…）。所以我們要問兩件事：
① 這個 演算法 好不好？（time complexity）
② 這個 問題 難不難？（lower bound、NP-complete）

爛演算法 + 快電腦 < 好演算法 + 慢電腦

課本的實驗：在 Intel 486 PC 上跑 quick sort（$O(n\log n)$），在 IBM SP2 超級電腦上跑 insertion sort（$O(n^2)$）。 資料少的時候 insertion sort 比較快，資料一多 quick sort 一定贏。所以演算法需要分析，不能只看硬體。

效率的四種看法

Amortized 例子：stack 上做 push a, b, push c, d, 再一次 pop 掉 b, c, d。單次 pop 可能很貴，但每個元素最多被 push 一次、pop 一次，所以 $n$ 個操作總成本 $\le 2n$。

六個有名問題：定義＋例子（直接背）

0/1 Knapsack NP-complete
給定 $n$ 個物品，物品 $P_i$ 有價值 $V_i$、重量 $W_i$，背包重量上限 $M$。選一個子集合，讓總重量 $\le M$，並讓總價值最大。每個物品只能拿（1）或不拿（0）。
Traveling Salesperson (TSP) NP-complete
給定平面上 $n$ 個點，找一條 closed tour，每個點恰好經過一次，並讓總長度最短。
Partition NP-complete
給定正整數集合 $S$，分成 $S_1,S_2$，$S_1\cap S_2=\varnothing$、$S_1\cup S_2=S$，且 $\sum S_1=\sum S_2$。
例：$S=\{1,7,10,4,6,8,3,13\}$ → $S_1=\{1,10,4,8,3\}$（26）、$S_2=\{7,6,13\}$（26）。
Art Gallery NP-complete
給定一個美術館（polygon），求最少需要幾個 guards、放在哪裡，才能監看整個美術館。
Minimum Spanning Tree Polynomial
Spanning tree：沒有 cycle、連到所有點的子圖。MST 是總權重最小的那棵。全部列出來有 $n^{n-2}$ 棵（$n=10$ 就有 $10^8$ 棵），但 greedy 很有效率：先找最短邊，再一直加上離目前這棵樹最近的點。應用：美國電話公司 5000 個城市的佈線。
Convex Hull Polynomial
給定平面上一群點，找出包住所有點的最小凸多邊形。用 divide-and-conquer 可以在 polynomial time 內解出。
1-Center Polynomial：找一個能蓋住所有 $n$ 個點的最小圓，$O(n)$。
0/1 Knapsack：課本的 8 個物品，$M=14$。點物品放進/拿出背包
課本的重點：看起來簡單的問題可能很難（0/1 knapsack），看起來很難的問題可能很簡單（MST 有 $n^{n-2}$ 棵樹，但 greedy 一下就解出來）。這就是要學演算法的原因。 另外，greedy 很快，但不保證最佳解（例如 greedy 用在 TSP 上就不一定是最佳解）。
題目：何謂 0/1 Knapsack Problem？舉例說明，它屬於何類問題？
(1) 定義：給定 $n$ 個物品，每個物品 $P_i$ 有價值 $V_i$、重量 $W_i$，及背包重量上限 $M$。 要選出一個物品子集合，使總重量不超過 $M$，且總價值最大；每個物品只能選或不選（0/1）。
(2) 例子：3 個物品 $(W,V)=(1,1),(2,2),(3,5)$，$M=4$。選第 1、3 個物品，總重 4，總價值 6 為最大。
(3) 屬於 NP-complete 問題。
題目：何謂 Convex Hull Problem？它的時間複雜度屬於何類問題？
(1) 給定平面上一群點，找出可以包住所有點的最小 convex polygon（凸多邊形）。
(2) 可用 divide-and-conquer 在 polynomial time 內解出（$O(n\log n)$），所以不是 NP-complete。

02Big-O：「當 n 很大時，最多是 g(n) 的某個倍數」

Chapter 2-1 / 2-2 · Asymptotic notation（每年必考的第二題）

怎麼量一個演算法快不快？直接寫程式計時會受程式設計師、語言、OS、compiler、電腦影響。所以我們改成選一個關鍵步驟（例如資料比較、資料搬移），數它要做幾次。

當 $n$ 很大時，$n^3+n$ 幾乎就是 $n^3$。Big-O 就是把這件事寫成正式的定義：
「我找得到一個倍數 $c$，從某個 $n_0$ 開始，$f(n)$ 永遠被 $c\cdot g(n)$ 壓在下面。」

三個定義（O = 最多、Ω = 至少、Θ = 剛好）

O：$f(n)=O(g(n))$ 若且唯若存在正常數 $c$ 與 $n_0$，使得對所有 $n\ge n_0$，$|f(n)|\le c\,|g(n)|$。（at most，upper bound）

Ω：$f(n)=\Omega(g(n))$ 若且唯若存在正常數 $c$ 與 $n_0$，使得對所有 $n\ge n_0$，$|f(n)|\ge c\,|g(n)|$。（at least，lower bound）

Θ：$f(n)=\Theta(g(n))$ 若且唯若存在正常數 $c_1,c_2,n_0$，使得對所有 $n\ge n_0$，$c_1|g(n)|\le|f(n)|\le c_2|g(n)|$。（至少又至多，即剛好）

例：$3n^2+2=\Omega(n^2)$，也 $=\Omega(n)$（lower bound 不只一個，一般寫最大的那個）；$3n^2+2=\Theta(n^2)$。

親手找 $c$ 和 $n_0$：$f(n)=2n^3+3n^2+n+1$ vs. $c\cdot n^3$

動手試試：把 $c$ 拉到 2 以下，黃線永遠追不上藍線（因為 $f(n)$ 的最高次項係數就是 2）。只要 $c>2$，一定存在某個 $n_0$。 考試時選一個最好證明的 $c$ 就好，不需要最小的。

考試萬用招：每一項都放大成最高次

當 $n\ge1$ 時，$n^3\ge n^2\ge n\ge1$，所以每個低次項都可以直接換成 $n^3$：

$$2n^3+3n^2+n+1\ \le\ 2n^3+3n^3+n^3+n^3\ =\ 7n^3$$
題目：(a) 寫出 $f(n)=O(g(n))$ 的定義。(b) 依上述定義分析 $2n^3+3n^2+n+1$ 的 $O(\ )$，需導過程。
(a) $f(n)=O(g(n))$ if and only if 存在兩個正常數 $c$ 和 $n_0$，使得對所有 $n\ge n_0$ 都有 $|f(n)|\le c\,|g(n)|$。
(b) 令 $f(n)=2n^3+3n^2+n+1$。當 $n\ge1$ 時，$n^2\le n^3$、$n\le n^3$、$1\le n^3$，所以
$|f(n)|=2n^3+3n^2+n+1\le 2n^3+3n^3+n^3+n^3=7n^3=7|n^3|$。
取 $c=7$、$n_0=1$，對所有 $n\ge n_0$ 都有 $|f(n)|\le c|n^3|$，所以 $f(n)=O(n^3)$。
其他考過的變形（點開）

$n^3+2n^2+1$（113 小考）：$n\ge1$ 時 $\le n^3+2n^3+n^3=4n^3$，取 $c=4,\ n_0=1$ → $O(n^3)$。

$2n^3+100n^2+6n+8$（114 期中）：$n\ge1$ 時 $\le(2+100+6+8)n^3=116n^3$，取 $c=116,\ n_0=1$ → $O(n^3)$。

$n\log n+2n+5$（113 期中）：$n\ge2$ 時 $\log_2 n\ge1$，所以 $2n\le2n\log n$、$5\le5n\log n$， 得 $\le n\log n+2n\log n+5n\log n=8n\log n$。取 $c=8,\ n_0=2$ → $O(n\log n)$。
注意 $n_0$ 要取 2：$n=1$ 時 $\log 1=0$，不等式不成立。

① 定義要寫出「存在 $c,n_0$」和「對所有 $n\ge n_0$」，少寫會扣分。
② 最後一定要明確寫出你選的 $c=?$、$n_0=?$。
③ $O(n^3)$ 的演算法 A 和 $O(n)$ 的演算法 B，B 不一定永遠比較快，只有 $n$ 夠大時才成立（課本例：A1 $=n^3$，A2 $=100n$，$n<10$ 時 A1 比較快）。

成長速度：記住這條順序

$$O(1)<O(\log n)<O(n)<O(n\log n)<O(n^2)<O(n^3)<O(2^n)<O(n!)<O(n^n)$$

03Straight Insertion Sort：像整理手上的撲克牌

Chapter 2-1 · Algorithm 2.1

左邊永遠是一疊已經排好的牌。每次拿起下一張牌 $x_j$，從右往左比，比它大的牌就往右挪一格，直到找到位置把牌插進去。
需要挪動的次數，就是「$x_j$ 左邊比它大的元素個數」，記作 $d_j$。整個分析都在算 $d_j$。 
Input:  x1, x2, ..., xn
Output: sorted sequence of x1, x2, ..., xn
For j := 2 to n do
Begin
    i := j - 1
    x := xj                         // data movement 1 次
    While x < xi and i > 0 do
    Begin
        x(i+1) := xi                // data movement，共 dj 次
        i := i - 1
    End
    x(i+1) := x                     // data movement 1 次
End
一步一步看：橘色＝手上拿的 x，藍色＝正在比較的元素，黑色＝已排好，虛線＝空格
x = –比較次數 0搬移次數 M 0Σdⱼ 0

分析 data movement：$M=\sum_{j=2}^{n}(2+d_j)=2(n-1)+\sum_{j=2}^{n}d_j$

每一輪固定搬 2 次（$x:=x_j$ 和 $x_{i+1}:=x$），再加上往右挪的 $d_j$ 次。

Best case：已經排好，例如 1, 2, 3, 4
每個 $d_j=0$
$M=2(n-1)=O(n)$
Worst case：反向排序，例如 4, 3, 2, 1
$d_j=j-1$（左邊每個都比它大）
$M=2(n-1)+\dfrac{n(n-1)}{2}=O(n^2)$

Average case：$x_j$ 落在每個名次的機率都是 $1/j$

$x_j$ 和它左邊的 $j-1$ 個元素一起看，共 $j$ 個元素。$x_j$ 是最大的 → $d_j=0$；第二大 → $d_j=1$；…；最小 → $d_j=j-1$。每種名次機率都是 $\frac1j$，所以

$$\overline{d_j}=\frac{1}{j}\sum_{k=0}^{j-1}k=\frac{1}{j}\cdot\frac{(j-1)j}{2}=\frac{j-1}{2}$$ $$M_{avg}=2(n-1)+\sum_{j=2}^{n}\frac{j-1}{2}=2(n-1)+\frac{n(n-1)}{4}=O(n^2)$$

題目：Straight insertion sort 若只用比較次數分析，worst case time complexity？（要寫過程）
令 $d_j$ 為 $x_j$ 左邊比 $x_j$ 大的元素個數。
Worst case 為資料反向排序（例：$n, n-1, \dots, 1$），此時每個 $x_j$ 都比左邊 $j-1$ 個元素小，$d_j=j-1$。
插入 $x_j$ 時要和左邊 $j-1$ 個元素各比較一次，才確定它是最小的、放到最前面，所以第 $j$ 輪比較 $j-1$ 次。
總比較次數 $=\sum_{j=2}^{n}(j-1)=1+2+\cdots+(n-1)=\dfrac{n(n-1)}{2}=O(n^2)$。
題目：以 data movement 分析 insertion sort 的 best / worst / average case。
$M=\sum_{j=2}^{n}(2+d_j)=2(n-1)+\sum_{j=2}^{n}d_j$。
Best（已排序）：$d_j=0$，$M=2(n-1)=O(n)$。
Worst（反向排序）：$d_j=j-1$，$M=2(n-1)+\frac{n(n-1)}{2}=O(n^2)$。
Average：$x_j$ 在前 $j$ 個元素中為第 $k$ 大的機率皆為 $\frac1j$，$d_j=0,1,\dots,j-1$， $\overline{d_j}=\frac{1}{j}\sum_{k=0}^{j-1}k=\frac{j-1}{2}$， $M=2(n-1)+\sum_{j=2}^{n}\frac{j-1}{2}=2(n-1)+\frac{n(n-1)}{4}=O(n^2)$。

04Inversion Table：換個角度數同一個總和

Chapter 2-1 · Another analysis

$(a_1,\dots,a_n)$ 是 $\{1,\dots,n\}$ 的一個 permutation。Inversion table $(d_1,\dots,d_n)$ 裡的 $d_j$ 是：在 permutation 中，數字 $j$ 所在位置左邊比 $j$ 大的個數。
注意是看「數字 j」，不是第 j 個位置的 $a_j$。
它跟前面 insertion sort 的 $d_j$（依位置算）意義不同，但總和一樣：兩者都是在數「有幾對 (大, 小) 是大的在左邊」，也就是 inversion 的對數。所以可以用 inversion table 分析 insertion sort。
輸入一個 1..n 的 permutation，看兩種 d 的算法

Best case：已排序 (1,2,3,4) → inversion table (0,0,0,0)。
Worst case：反向 (4,3,2,1) → (3,2,1,0)，$d_i=n-i$，總和 $1+2+\cdots+(n-1)=\frac{n(n-1)}{2}$。
Average case 用這個方法不好想，用前面的方法比較好想。

05Binary Search：每問一次，砍掉一半

Chapter 2-1 · 期中考 10% 的推導題

在排好序的序列裡找 $x$：每次看中間那一個。比它小就往左半找，比它大就往右半找。 每比一次，範圍砍半；$n$ 砍到剩 1 個只要 $\log_2 n$ 次。所以 sequential search 是 $O(n)$，binary search 是 $O(\log n)$。 
Input: A sorted array a1, a2, ..., an, and x
Output: j if aj = x and 0 if no j exists
i := 1                      // first entry
m := n                      // last entry
While i ≦ m do
Begin
    j := ⌊(i+m)/2⌋          // e.g. (1+8)/2 = 4.5 → 取 4（取較前面）
    If x = aj then output j and stop
    If x < aj then m := j - 1
    else i := j + 1
End
j := 0
output j
課本例子：在 1 4 5 7 9 10 12 15 中找 x

把每次比較畫成一棵樹（$n=2^k-1$，例如 $k=4,n=15$）

點任一個圓圈（找到）或方塊（找不到），看要比較幾次
第 i 層有 $2^{i-1}$ 個數，找到它們都要比 i 次。
  • Best case：第一次就找到，1 次 = $O(1)$
  • Worst case：走到樹底，$\lfloor\log_2 n\rfloor+1$ 次 = $O(\log n)$
  • Average case：$O(\log n)$，推導如下

Average case 推導（期中考必考，小考也可能）

假設 $n=2^k-1$。有 $n$ 種「找到」的情況，和 $n+1$ 種「找不到」的情況（樹底的方塊），共 $2n+1$ 種，假設機率都一樣。

  • 找到：比較 $i$ 次的有 $2^{i-1}$ 個，$i=1,\dots,k$ → 總共 $\sum_{i=1}^{k}i\,2^{i-1}$
  • 找不到：每種都比較 $k$ 次 → 總共 $k(n+1)$
$$A(n)=\frac{1}{2n+1}\left(\sum_{i=1}^{k}i\,2^{i-1}+k(n+1)\right)$$

關鍵公式：$\displaystyle\sum_{i=1}^{k}i\,2^{i-1}=2^k(k-1)+1$。代入 $n+1=2^k$：

$$A(n)=\frac{2^k(k-1)+1+k\,2^k}{2^{k+1}-1}=\frac{(2k-1)2^k+1}{2^{k+1}-1}\approx k-\tfrac12$$

而 $k=\log_2(n+1)$，所以 $A(n)=O(\log n)$。

證明 $\sum_{i=1}^{k}i\,2^{i-1}=2^k(k-1)+1$ ── 方法一：數學歸納法

$k=1$：左邊 $=1\cdot2^0=1$，右邊 $=2^1(0)+1=1$，成立。

假設 $k=m$ 成立：$\sum_{i=1}^{m}i\,2^{i-1}=2^m(m-1)+1$。

證 $k=m+1$：把第 $m+1$ 項獨立出來：

$$\sum_{i=1}^{m+1}i\,2^{i-1}=2^m(m-1)+1+(m+1)2^m=2^m(2m)+1=2^{m+1}\cdot m+1=2^{m+1}\big((m+1)-1\big)+1$$

等於右邊，得證。

證明 ── 方法二：微積分（等比級數兩邊微分） $$\sum_{i=0}^{k}x^{i}=\frac{1-x^{k+1}}{1-x}\quad\xrightarrow{\ \frac{d}{dx}\ }\quad\sum_{i=1}^{k}i\,x^{i-1}=\frac{-(k+1)x^{k}(1-x)+(1-x^{k+1})}{(1-x)^2}$$

把 $x=2$ 代入，分母 $(1-2)^2=1$：

$$\sum_{i=1}^{k}i\,2^{i-1}=(k+1)2^{k}+1-2^{k+1}=2^k(k-1)+1$$
題目：Derive the average time complexity of binary search.
設 $n=2^k-1$，把 binary search 的過程畫成一棵 complete binary tree，共 $k$ 層，第 $i$ 層有 $2^{i-1}$ 個 node，找到它們要比較 $i$ 次。
成功的情況有 $n$ 種，總比較次數為 $\sum_{i=1}^{k}i\,2^{i-1}$；失敗的情況有 $n+1$ 種，每種比較 $k$ 次。假設 $2n+1$ 種情況機率相等：
$A(n)=\dfrac{\sum_{i=1}^{k}i\,2^{i-1}+k(n+1)}{2n+1}$。
其中 $\sum_{i=1}^{k}i\,2^{i-1}=2^k(k-1)+1$（可用歸納法證明），且 $n+1=2^k$，
$A(n)=\dfrac{2^k(k-1)+1+k2^k}{2^{k+1}-1}=\dfrac{(2k-1)2^k+1}{2^{k+1}-1}\approx k-\frac12=\log_2(n+1)-\frac12$。
所以 average case 為 $O(\log n)$。

06Straight Selection Sort：每次挑最小的就定位

Chapter 2-2 · 重點是 flag change 的 average case

第 $j$ 輪從 $a_j \sim a_n$ 中找出最小的，跟 $a_j$ 交換。用一個 flag $f$ 記住「目前看到最小的位置」。
有兩種操作要數：
① Comparison（$a_k<a_f$）：次數固定 $(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}$，不隨資料改變。
② Flag change（$f:=k$）：隨資料改變。只算 $f:=k$，不算 $f:=j$。 
For j := 1 to n-1 do
Begin
    f := j                           // 不算
    For k := j+1 to n do
        If ak < af then f := k        // comparison；f := k 是 flag change
    aj ↔ af
End

Average flag change 的思路：三步

$A(n)$ = 排序 $n$ 個元素的平均 flag change 數。找完最小值後，剩下 $n-1$ 個元素還是隨機的，所以

$$A(n)=X_n+A(n-1)$$

$X_n$ = 在 $n$ 個元素中只找一次最小值的平均 flag change 數。步驟：求 $P_n(k)$ → 求 $X_n$ → 求 $A(n)$。

$P_n(k)$ = 在 $n$ 個元素中找最小值，剛好做 $k$ 次 flag change 的機率。初始條件：$P_1(0)=1$、$P_1(k)=0\ (k\ne0)$；$P_n(k)=0$ if $k\ge n$（最多只能改 $n-1$ 次，例如 3, 2, 1）。

遞迴關係：看最後一個元素 $a_n$。每種 permutation 機率相同，所以 $a_n$ 是全部中最小的機率是 $\frac1n$。
・$a_n$ 是最小（機率 $\frac1n$）：掃到它時一定會多 1 次 flag change。
・$a_n$ 不是最小（機率 $\frac{n-1}{n}$）：不會多 change。 $$P_n(k)=\frac{1}{n}P_{n-1}(k-1)+\frac{n-1}{n}P_{n-1}(k)$$ $$X_n=\sum_k k\,P_n(k)=X_{n-1}+\frac1n\quad\Rightarrow\quad X_n=\frac12+\frac13+\cdots+\frac1n=H_n-1$$
用電腦窮舉所有 permutation 驗證：$X_n$ 真的等於 $H_n-1$ 嗎？

最後把每一輪加起來（$H_n\approx\ln n$）：

$$A(n)=\sum_{i=2}^{n}X_i=\sum_{i=2}^{n}(H_i-1)=(n+1)H_n-2n\approx n\ln n=O(n\log n)$$

題目：分析 straight selection sort 的 average flag change 數。
令 $P_n(k)$ 為在 $n$ 個元素中找最小值時發生 $k$ 次 flag change 的機率。最後一個元素為最小值的機率為 $\frac1n$，此時多一次 flag change，因此 $P_n(k)=\frac1nP_{n-1}(k-1)+\frac{n-1}{n}P_{n-1}(k)$。
找一次最小值的平均 flag change 數 $X_n=\sum_k kP_n(k)=X_{n-1}+\frac1n$，且 $X_1=0$，所以 $X_n=\frac12+\cdots+\frac1n=H_n-1$。
$A(n)=X_n+A(n-1)=\sum_{i=2}^{n}(H_i-1)$，$H_i\approx\ln i$，所以 $A(n)=O(n\log n)$。
Comparison 次數不隨資料改變，固定為 $\frac{n(n-1)}{2}=O(n^2)$。

07Quick Sort：選一個人當標準，比他小站左邊、大站右邊

Chapter 2-2 · Divide-and-conquer（113 小考第三題）

取第一個元素 $X$ 當 pivot。把比 $X$ 小的放到左邊、比 $X$ 大的放到右邊，$X$ 就到了最終位置。然後左右兩邊遞迴做同樣的事。
用兩個指標實作：$j$ 從右邊往左走，找到小於 $X$ 的就跟 $X$ 交換；$i$ 從左邊往右走，找到大於 $X$ 的就跟 $X$ 交換；重複到 $i\ge j$。一輪 scan 是 $O(n)$。 
Algorithm QuickSort(f, l)
Input: af, af+1, ..., al
If f ≧ l then Return
X := af                         // 第一個元素 = 用來分割的元素
i := f ;  j := l
While i < j do
Begin
    While aj ≧ X do j := j - 1     // 從 j 過來，直至小於 X
    ai ↔ aj
    While ai ≦ X do i := i + 1     // 從 i 過去，直至大於 X
    ai ↔ aj
End
QuickSort(f, j-1)
QuickSort(j+1, l)

Best case：每次剛好切一半 → $O(n\log n)$

每一層加起來都約 $n$ 次比較，總共 $\log n$ 層。用遞迴式寫：

$$T(n)=2T\!\left(\tfrac n2\right)+cn,\qquad T(1)=0$$ $$\begin{aligned}T(n)&=2T(\tfrac n2)+cn=4T(\tfrac n4)+2cn=8T(\tfrac n8)+3cn=\cdots\\&=2^kT(\tfrac{n}{2^k})+kcn\quad(n=2^k,\ k=\log_2 n)\\&=nT(1)+cn\log_2 n=O(n\log n)\end{aligned}$$

Worst case：每次 pivot 都是最小或最大 → $O(n^2)$

例如已排序的 1 2 3 4 5：每次只切掉 pivot 一個，比較次數 $(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}=O(n^2)$。

已經排好的資料是 quick sort 的 worst case（不是 best case）！這跟 insertion sort 剛好相反。

Average case：$O(n\log n)$

假設 split 後變成 $s$ 和 $n-s$ 兩堆，$s=1,\dots,n$ 機率都一樣，這一輪花 $cn$：

$$T(n)=\frac1n\sum_{s=1}^{n}\big(T(s)+T(n-s)\big)+cn,\qquad T(0)=0$$
推導（課本的「錯位相減」） $$nT(n)=2T(1)+2T(2)+\cdots+2T(n-1)+T(n)+cn^2$$ $$(n-1)T(n)=2T(1)+\cdots+2T(n-1)+cn^2\qquad(1)$$

$n$ 用 $n-1$ 代入：

$$(n-2)T(n-1)=2T(1)+\cdots+2T(n-2)+c(n-1)^2\qquad(2)$$

(1) − (2)：

$$(n-1)T(n)-(n-2)T(n-1)=2T(n-1)+c\big(n^2-(n-1)^2\big)=2T(n-1)+c(2n-1)$$ $$(n-1)T(n)=nT(n-1)+c(2n-1)\quad\Big/\ n(n-1)\quad\Rightarrow\quad\frac{T(n)}{n}=\frac{T(n-1)}{n-1}+c\Big(\frac1n+\frac1{n-1}\Big)$$

一路遞迴到 $T(1)=0$（boundary condition），除了 $\frac1n$ 和 $1$ 之外每一項都出現兩次：

$$\frac{T(n)}{n}=c\Big(\frac1n+\frac1{n-1}\Big)+c\Big(\frac1{n-1}+\frac1{n-2}\Big)+\cdots+c\Big(\frac12+1\Big)=c(H_n-1)+cH_{n-1}$$

Harmonic number $H_n=1+\frac12+\cdots+\frac1n\approx\ln n$，所以

$$T(n)=n\big(c(H_n-1)+cH_{n-1}\big)\approx 2cn\ln n=O(n\log n)$$

082-D Ranking：誰被誰「完全壓過」

Chapter 2-2 · Divide-and-conquer（114 小考第四題）

1-D：$a_i$ dominates $a_j$ if $a_i>a_j$。$a_i$ 的 rank = 被 $a_i$ dominate 的元素個數。直接 sort 就知道 rank（3 5 1 7 → 1 3 5 7 的 rank 是 0 1 2 3）。
2-D：$A=(a_1,a_2)$ dominates $B=(b_1,b_2)$ iff $a_1>b_1$ 且 $a_2>b_2$（兩個維度都要成立）。 點 $x$ 的 rank = 被 $x$ dominate 的點的個數。有些點互相無法比較（incomparable）。
暴力法：每個點檢查其他所有點 → $O(n)\times n$ 個點 $=O(n^2)$。用 divide-and-conquer 可以做到 $O(n\log^2 n)$。
Divide-and-conquer 的關鍵觀察：用一條垂直線 $L$（x 的中位數）把點分成左邊 A、右邊 B 兩半。
・A 裡的點 x 座標都比 B 小，所以 A 的點不可能 dominate B 的點，A 的 rank 遞迴求完就是答案。
・B 的點 x 座標一定比 A 的點大，所以只要比 y 值：B 中點的最終 rank = 它在 B 裡的 rank + A 中 y 值比它小的點數。
按步驟看 D&C：Step 1 → Step 2 → Step 3
題目：(a) 寫出 2-D ranking problem 的 divide-and-conquer 演算法。(b) 寫出每步驟及整個演算法的時間複雜度。
Input：平面上 $n$ 個點的集合 $S$。Output：每個點的 rank。
Step 1：若 $S$ 只有一個點，rank 為 0，return。否則找出 x 值的中位數，用垂直線 $L$ 把 $S$ 分成 A（左）、B（右）兩個大小相同的子集合。 ── 找 median：$O(n)$（先 sort 再取第 $n/2$ 個是 $O(n\log n)$，Chapter 6 有 $O(n)$ 的方法）。
Step 2：遞迴求出 A 中各點的 rank 和 B 中各點的 rank。── $2T(\frac n2)$
Step 3：把 A、B 的點依 y 值排序，由小到大掃描；對 B 中每個點，把它的 rank 加上 A 中 y 值比它小的點數。 ── sort $O(n\log n)$ + scan $O(n)$ $=O(n\log n)$。

$T(n)=2T(\frac n2)+c_1n+c_2n\log n\le2T(\frac n2)+cn\log n$，令 $n=2^k$：
$T(n)\le2T(\frac n2)+cn\log n$
$\le4T(\frac n4)+cn\log\frac n2+cn\log n$
$\le\cdots\le nT(1)+cn\big(\log n+\log\frac n2+\cdots+\log2\big)$
$=nT(1)+cn\big(\log n+(\log n-1)+\cdots+1\big)$　← 等差級數，共 $\log n$ 項
$=nT(1)+cn\cdot\dfrac{\log n(\log n+1)}{2}=O(n\log^2 n)$。
Worst case 和 average case 都是 $O(n\log^2 n)$，比暴力法 $O(n^2)$ 好很多。

09Lower Bound：問題本身有多難？

Chapter 2-2 · Measurement of the difficulty of a problem

演算法的 time complexity 是「這個方法要多久」，從上面壓住（O）。
問題的 lower bound 是「任何方法至少要多久」，從下面撐住（Ω）。
兩者碰在一起時，就不能再改進了 → optimal algorithm。
Definition：A lower bound of a problem is the least time complexity required for any algorithm which can be used to solve this problem.
分成 worst case lower bound 和 average case lower bound。
Lower bound 不唯一。例如 sorting：$\Omega(1)$、$\Omega(n)$、$\Omega(n\log n)$ 都是 lower bound，前兩個是 trivial 的（至少要讀資料、至少要 scan 過 $n$ 個元素）。要找最高的那一個。
不可能試遍所有演算法，所以要用理論證明。
Sorting 的 lower bound 為什麼不是 $\Omega(n^2)$？
因為 lower bound 是「任何演算法至少要花的時間」。已知 heap sort 的 worst case 是 $O(n\log n)$，所以真正的 lower bound $\le n\log n$，不可能是 $n^2$。 不能用 quick sort 的 worst case $O(n^2)$ 來判斷，因為只要有一個演算法比較快，lower bound 就不會超過它。
三種情況：拖動看看「最好的演算法」和「問題的 lower bound」
Optimal algorithm：演算法的 time complexity = 問題的 lower bound。此時 lower bound 和演算法都不能再改進。（這裡的 optimal 指 efficiency，不是 accuracy。）
剩下的難題：如何得到 lower bound？很難。
考過的延伸題：排序 1～K 範圍內的 n 個正整數（K 是常數），lower bound 還是 $\Omega(n\log n)$ 嗎？

不是。$\Omega(n\log n)$ 是「只能用比較」的排序方法的 lower bound。如果數字範圍只有 1～K，可以開 K 個計數格子（counting sort）， 掃一遍數每個值出現幾次，再依序輸出，時間 $O(n+K)=O(n)$。而任何方法至少要讀過 $n$ 個數，所以這個問題的 lower bound 是 $\Omega(n)$，counting sort 是 optimal。

一、(2%) 何謂 Traveling Salesperson Problem？它的時間複雜度屬於何類問題？
給定平面上 $n$ 個點，找一條 closed tour，每個點恰好經過一次，且總長度最短。屬於 NP-complete 問題（目前沒有 polynomial time 的演算法，也沒有被證明一定要 exponential time）。
一、(2%) 何謂 Partition Problem？舉例。屬於何類問題？
給定一個正整數集合 $S$，是否能分成 $S_1,S_2$，$S_1\cap S_2=\varnothing$、$S_1\cup S_2=S$，且 $S_1$ 的總和等於 $S_2$ 的總和。
例：$S=\{1,7,10,4,6,8,3,13\}$，$S_1=\{1,10,4,8,3\}$、$S_2=\{7,6,13\}$，總和都是 26。屬於 NP-complete。
一、(2%) 何謂 Minimum Spanning Tree Problem？屬於何類問題？
給定 weighted graph $G$，找一棵包含 $G$ 所有 vertices 的 spanning tree（無 cycle 且所有點連通），使總 weight 最小。 雖然可能有 $n^{n-2}$ 棵 spanning tree，但用 greedy method 可以在 polynomial time 內找到最佳解，所以不是 NP-complete。
二、(2%) (a) 寫出 $f(n)=\Omega(g(n))$ 的定義。(b) 分析 $3n^2+2$ 的 $\Omega(\ )$。
(a) $f(n)=\Omega(g(n))$ iff 存在正常數 $c,n_0$，使得對所有 $n\ge n_0$，$|f(n)|\ge c|g(n)|$。
(b) 對所有 $n\ge1$，$3n^2+2\ge3n^2\ge1\cdot n^2$，取 $c=1,n_0=1$，所以 $3n^2+2=\Omega(n^2)$。（又因為 $\le5n^2$，所以也是 $\Theta(n^2)$。）
二、(2%) (a) 寫出 $f(n)=O(g(n))$ 的定義。(b) 分析 $4n^2+5n\log n+9$ 的 $O(\ )$。
(a) 存在正常數 $c,n_0$，使得對所有 $n\ge n_0$，$|f(n)|\le c|g(n)|$。
(b) 當 $n\ge2$：$\log n\le n$，所以 $5n\log n\le5n^2$；$9\le9n^2$。
$4n^2+5n\log n+9\le4n^2+5n^2+9n^2=18n^2$。取 $c=18,n_0=2$，所以 $f(n)=O(n^2)$。
三、(2%) Straight insertion sort 以 data movement 分析 best case 和 worst case（要寫過程）。
$M=\sum_{j=2}^{n}(2+d_j)$，$d_j$ 為 $x_j$ 左邊比它大的個數。
Best：已排序，$d_j=0$，$M=2(n-1)=O(n)$。
Worst：反向排序，$d_j=j-1$，$M=2(n-1)+\sum_{j=2}^{n}(j-1)=2(n-1)+\frac{n(n-1)}{2}=O(n^2)$。
三、(2%) Quick sort 的 worst case time complexity？需導過程。
Worst case：每次用來 split 的元素都是最小（或最大）的，例如已排序的 $1,2,\dots,n$。每次只能分出 1 個元素，剩下 $n-1$ 個繼續遞迴。
比較次數 $=(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}=O(n^2)$。
三、(2%) Binary search 的 worst case 和 best case 各要比較幾次？
Best：第一次比較中間元素就找到，1 次，$O(1)$。
Worst：每次範圍減半，直到剩 1 個元素，共 $\lfloor\log_2 n\rfloor+1$ 次，$O(\log n)$。
三、(2%) Straight selection sort 中，comparison 和 flag change 的 best / worst / average 各為何？
Comparison 不隨資料改變：固定 $\frac{n(n-1)}{2}$，best/worst/average 都是 $O(n^2)$。
Flag change：best $O(1)$（已排序，0 次）、worst $O(n^2)$、average $A(n)=\sum_{i=2}^{n}(H_i-1)=O(n\log n)$。

四、(2%) 何謂 optimal algorithm？Sorting 的 lower bound 為何不是 $\Omega(n^2)$？
