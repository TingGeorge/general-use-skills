Chapter 1 — Introduction

1.1 What is an algorithm, and why study it?

An algorithm is a description (procedure) of the steps that solve a problem. Example, “going to work”: get up → brush teeth → eat breakfast → get dressed → pack the briefcase → take the bus. This course is about how computers solve problems.

One problem can have many algorithms. Sorting 1, 3, 5, 4 → 1, 3, 4, 5 can be done with insertion sort, quick sort, and others.

Why study algorithms:

  1. To learn strategies for designing efficient algorithms (greedy, divide-and-conquer, …).
  2. To understand that some problems are inherently hard: the NP-complete problems (e.g. TSP).

A good algorithm vs. a fast computer

Textbook experiment: quick sort on an Intel 486 PC vs. insertion sort on an IBM SP2 supercomputer.

  • For large inputs, quick sort (on the slow PC) wins.
  • For small inputs, insertion sort wins.

Conclusion: a bad algorithm on a fast computer loses to a good algorithm on a slow computer once $n$ is large enough. That is why we analyze algorithms — looking at the best, worst, and average case, because running time depends on the data (insertion sort does different amounts of work on 1,2,3,4,5 and on 1,3,5,2,4).

The two sorting examples from the textbook

Insertion sort: insert elements one by one into their correct place.
11, 7, 14, 1, 5, 9, 10 → 7,11 → 7,11,14 → 1,7,11,14 → 1,5,7,11,14 → 1,5,7,9,11,14 → 1,5,7,9,10,11,14

Quick sort (divide-and-conquer, recursive): use the first element as the pivot, split the list into “smaller / pivot / larger”, then recurse on both sides.
10, 5, 1, 17, 14, 8, 7, 26, 21, 3 → (5,1,8,7,3) (10) (17,14,26,21) → … → 1,3,5,7,8,10,14,17,21,26

1.2 Seven famous problems (the question bank for Quiz question ①)

The quiz asks: “What is the X problem? (Give the definition or describe it.) Give an example. Which class does its time complexity belong to?” For each problem, remember three things: definition, one example, class.

(1) 0/1 Knapsack Problem NP-completeQuiz 113

Definition: given $n$ items, where item $P_i$ has value $V_i$ and weight $W_i$, and a knapsack with weight limit $M$, choose a subset of items whose total weight does not exceed $M$ and whose total value is maximized. “0/1” means each item is either left out (0) or taken whole (1) — you cannot take part of an item.

0/1 的意思：每個物品只能「整個拿」或「不拿」，不能切一半拿。

$$\max \sum_{i=1}^{n} V_i x_i \quad \text{subject to} \quad \sum_{i=1}^{n} W_i x_i \le M,\quad x_i \in \{0, 1\}$$

Textbook example: $M = 14$

Optimal solution: P1, P2, P3, P5 — total weight $7+3+3+1 = 14 \le 14$, total value $10+5+1+3 = \mathbf{19}$ (verified to be the maximum by exhaustive search).

It looks easy but is actually hard: $n$ items give $2^n$ possible subsets, and no polynomial algorithm is known → NP-complete.

(2) Traveling Salesperson Problem (TSP) NP-complete

Definition: given $n$ points in the plane, find a closed tour that visits every point exactly once and has minimum total length.
Example: a salesperson must visit 5 cities once each and return home; find the shortest route.

(3) Partition Problem NP-complete

Definition: given a set $S$ of positive integers, split $S$ into $S_1$ and $S_2$ with equal sums:

$$S_1 \cap S_2 = \varnothing,\qquad S_1 \cup S_2 = S,\qquad \sum_{a \in S_1} a = \sum_{a \in S_2} a$$

Example: $S = \{1, 7, 10, 4, 6, 8, 3, 13\}$, $S_1 = \{1, 10, 4, 8, 3\}$ (sum 26), $S_2 = \{7, 6, 13\}$ (sum 26).

(4) Art Gallery Problem NP-complete

Definition: given an art gallery (a polygon), find the minimum number of guards and their positions so that the whole gallery is watched.

(5) Minimal Spanning Tree (MST) Polynomial

A spanning tree is a tree in the graph (no cycle) that connects all vertices.
Definition: given a weighted graph $G$, find a spanning tree $T$ with minimum total weight.

Application: a US phone company connecting 5000 cities with the least total cable length.

Why brute force fails: $n$ vertices can have up to $n^{n-2}$ spanning trees (a proven result). $n = 10 \Rightarrow 10^8$; $n = 100 \Rightarrow 10^{196}$. This is a combinatorial explosion.

Greedy method: start from any vertex and repeatedly add the vertex closest to the current tree. For MST this is guaranteed optimal and efficient; for other problems (e.g. TSP) greedy is not always optimal.

Greedy（貪婪法）：每一步都選「眼前最好」的選擇。對 MST 一定得到最佳解，但對 TSP 不保證。

The one sentence the textbook wants you to remember Problems that look easy may be hard (e.g. 0/1 knapsack); problems that look hard may be easy (e.g. minimum spanning tree). That is why we study algorithms.

(6) 1-Center Problem Polynomial, $O(n)$

Definition: given $n$ points, find the smallest circle that covers all of them. Solvable in $O(n)$ → not NP-complete (a multiple-choice question on the 114 midterm).

(7) Convex Hull Problem PolynomialQuiz 114

Definition: given a set of points in the plane, find the smallest convex polygon containing all of them.
“Convex” means: for any two points inside the polygon, the whole segment between them stays inside. Picture a nail at every point and a rubber band stretched around all the nails — the band's shape is the convex hull.

Convex（凸）：多邊形內任兩點的連線都在多邊形裡面。想成用橡皮筋套住所有釘子。

Interactive: click to add points — watch the convex hull update

Solvable by divide-and-conquer in polynomial time ($O(n\log n)$) → not NP-complete.

Chapter 2-1 — The Complexity of Algorithms

Three criteria for a good algorithm: correctness, short running time, small memory use. The book focuses on time.

How do we measure time? Timing a program in seconds is unreliable: it depends on the programmer, the language, the OS, the compiler, and the machine. The formal approach: choose a basic step (e.g. a data comparison $\lt,\ \gt,\ =$, or a data movement) and count how many times it happens.

Time complexity has best-case, average-case, and worst-case versions (plus amortized), and it is a function of the problem size $n$: $n\uparrow \Rightarrow$ time $\uparrow$.

Difficulty of the analysis: best case is easiest, worst case is second, average case is hardest.

2.1 Asymptotic notation: Big-O definition and derivation ★Every year

In one lineBig-O = “at most a constant times $g(n)$, once $n$ is big enough”. To prove it, show a $c$ and an $n_0$.

For large $n$, $n^3 + n \approx n^3$ (at $n = 1000$ the extra $n$ is one part in a million), so we only care about the highest-order term and write $O(n^3)$.

$$\begin{aligned} &\textbf{Definition: } f(n) = O(g(n)) \iff \\ &\exists\, c > 0,\ n_0 > 0 \ \text{ such that } \ |f(n)| \le c\,|g(n)| \ \text{ for all } n \ge n_0 \end{aligned}$$

In plain words: for large enough $n$, the number of steps $f(n)$ is at most a constant multiple of $g(n)$. O means “at most” (an upper bound).

直覺：當 n 夠大時，f(n) 最多是 g(n) 的常數倍。c 是那個倍數，n₀ 是「從哪裡開始成立」。

$g(n)$ is not unique: $n^3 + n = O(n^3)$ and also $= O(n^4)$, but we normally give the smallest (tightest) $g(n)$.

Derivation template: “raise every term to the highest power”

For $n \ge 1$ we have $n \le n^2 \le n^3$, so every lower-order term can be replaced by $n^3$ (this only makes it bigger):

$$\begin{aligned} f(n) &= n^3 + 2n^2 + 1 \\ &\le n^3 + 2n^3 + n^3 && (n \ge 1 \Rightarrow n^2 \le n^3,\ 1 \le n^3) \\ &= 4n^3 \end{aligned}$$ $$\text{Take } c = 4,\ n_0 = 1:\quad |f(n)| \le 4\,|n^3| \ \text{ for all } n \ge n_0$$ $$\therefore\ f(n) = O(n^3)$$
Interactive: find $c$ and $n_0$ yourself

Drag $c$. The green zone is where $f(n) \le c\cdot g(n)$ holds for good — it starts at $n_0$.

What to write on the exam (2 points) (a) $f(n) = O(g(n))$ iff there exist positive constants $c, n_0$ such that $|f(n)| \le c\,|g(n)|$ for all $n \ge n_0$.
(b) The derivation above. Always state the values of $c$ and $n_0$, then conclude $O(n^3)$.

Practice (actual past exam questions)

$2n^3 + 3n^2 + n + 1$ (Quiz 114)
$$n \ge 1:\quad 2n^3 + 3n^2 + n + 1 \le 2n^3 + 3n^3 + n^3 + n^3 = 7n^3$$ $$c = 7,\ n_0 = 1 \ \Rightarrow\ f(n) = O(n^3)$$

Another answer that got full marks: $f(n) = n^3\left(2 + \dfrac{3n^2+n+1}{n^3}\right)$, and for $n \ge 2$ the bracket is $\le 4$, so $c = 4$, $n_0 = 2$. Both are fine — $c$ is not unique.

$n\log n + 2n + 5$ (113 midterm)
$$n \ge 2 \Rightarrow \log_2 n \ge 1 \Rightarrow n \le n\log n,\ \ 1 \le n\log n$$ $$n\log n + 2n + 5 \le n\log n + 2n\log n + 5n\log n = 8\,n\log n$$ $$c = 8,\ n_0 = 2 \ \Rightarrow\ f(n) = O(n\log n)$$

Note: $n_0$ must be 2, because at $n = 1$, $\log 1 = 0$ and the inequality fails.

$2n^3 + 100n^2 + 6n + 8$ (114 midterm)
$$n \ge 1:\quad 2n^3 + 100n^2 + 6n + 8 \le 2n^3 + 100n^3 + 6n^3 + 8n^3 = 116n^3$$ $$c = 116,\ n_0 = 1 \ \Rightarrow\ f(n) = O(n^3)$$

Does the constant $c$ matter?

A1 is $O(n^3)$ at 1 time unit per step; A2 is $O(n)$ at 100 time units per step. Compare $n^3$ with $100n$:

  • At $n = 10$ they tie; for $n \lt 10$ A1 is faster; for $n \gt 10$ A2 is faster.
Interactive: does the constant matter?

A1 costs $n^3$. A2 costs $c \cdot n$. Make A2's constant huge — it still wins eventually.

Conclusion: an $O(n)$ algorithm is not always faster than an $O(n^3)$ one, but it is always faster once $n$ is large enough, whatever the constant.

2.3 Straight Insertion Sort ★

In one lineTake each element and slide it left into the sorted part.Best $O(n)$Worst $O(n^2)$Avg $O(n^2)$

Algorithm 2.1

Input:  x[1], x[2], ..., x[n]
Output: the sorted sequence of x[1..n]

For j := 2 to n do
Begin
    i := j - 1
    x := x[j]                // 1 data movement (take x[j] out)
    While x < x[i] and i > 0 do
    Begin
        x[i+1] := x[i]       // shift right; happens d[j] times
        i := i - 1
    End
    x[i+1] := x              // 1 data movement (put x back)
End

Analysis by data movement

The number of movements in round $j$ is $2$ (take $x$ out and put it back) $+\ d_j$, where $d_j$ = the number of elements to the left of $x_j$ that are larger than $x_j$.

dj：第 j 個元素「左邊比它大」的個數，也就是它要往左移動幾格。

$$M = \sum_{j=2}^{n} (2 + d_j) = 2(n-1) + \sum_{j=2}^{n} d_j$$

Best case (already sorted, e.g. 1, 2, 3, 4): $d_j = 0$

$$M = 2(n-1) + 0 = O(n)$$

Worst case (reverse sorted, e.g. 4, 3, 2, 1): $d_j = j - 1$

$$M = 2(n-1) + \big[1 + 2 + \cdots + (n-1)\big] = 2(n-1) + \frac{n(n-1)}{2} = O(n^2)$$

Average case: $x_j$ has $j-1$ elements to its left. If $x_j$ is the largest of these $j$ elements → $d_j = 0$; second largest → $1$; …; smallest → $j-1$. Assume each case has the same probability $\frac{1}{j}$:

平均情況的想法：xj 在前 j 個數中排第幾大，每種排名機率都是 1/j，所以 dj 平均是 0 到 j−1 的平均值。

$$E[d_j] = \frac{1}{j}\big(0 + 1 + 2 + \cdots + (j-1)\big) = \frac{1}{j}\cdot\frac{j(j-1)}{2} = \frac{j-1}{2}$$ $$\begin{aligned} M &= \sum_{j=2}^{n}\left(2 + \frac{j-1}{2}\right) = 2(n-1) + \frac{1}{2}\cdot\frac{n(n-1)}{2} \\ &= 2(n-1) + \frac{n(n-1)}{4} = \frac{(n-1)(n+8)}{4} = O(n^2) \end{aligned}$$

($\frac{(n-1)(n+8)}{4}$ was checked by computer against the average over all permutations for $n = 4, 5, 6$.)

See it: where do the data movements come from?

Each bar is one round $j$: 2 grey blocks (take out + put back) plus $d_j$ colored blocks (shifts).

Analysis by comparisons only (Quiz 114 question)

In round $j$'s while loop, every shift costs one comparison; if the loop stops because $x \ge x_i$, there is one extra comparison.

  • Best case (already sorted): each round makes 1 comparison and stops → $n - 1$ comparisons in total $= O(n)$. (113 midterm true/false “Insertion sort needs $(n-1)$ comparisons in the best case” → True.)
  • Worst case (reverse sorted): in round $j$, $x$ is compared with all $j-1$ elements on its left, and the loop stops because $i = 0$ (no extra comparison) → $j-1$ comparisons.
$$\text{Worst-case comparisons} = \sum_{j=2}^{n}(j-1) = 1 + 2 + \cdots + (n-1) = \frac{n(n-1)}{2} = O(n^2)$$
Summary: Straight Insertion Sort Best $O(n)$, worst $O(n^2)$, average $O(n^2)$. The time complexity equals the data-movement complexity.

2.4 Another analysis: the Inversion Table

Treat the list to be sorted as a permutation $(a_1, \dots, a_n)$ of $\{1, 2, \dots, n\}$.

$$\begin{aligned} &\textbf{Inversion table } (d_1, d_2, \dots, d_n): \\ &d_j = \#\text{ elements to the left of the number } j \text{ that are greater than } j \end{aligned}$$
CarefulGreater than the number $j$, not greater than $a_j$. This is a different $d_j$ from insertion sort's $d_j$ (which is indexed by position $j$).

易錯：inversion table 是看「數字 j」，insertion sort 的 dj 是看「第 j 個位置」。兩者意義不同，但總和相同。

Example: permutation $(7\ 5\ 1\ 4\ 3\ 2\ 6)$

Number $j$1234567
Larger numbers to its left7,57,5,4,37,5,47,577—
Inversion table $d_j$2432110
Insertion-sort $d_j$ (by position)0122341

The two rows are rearrangements of each other, so their sums are equal:

$$2+4+3+2+1+1+0 \;=\; 0+1+2+2+3+4+1 \;=\; 13$$

That is why the inversion table can be used to analyze insertion sort.

  • Best: sorted $(1,2,3,4)$ → inversion table $(0,0,0,0)$ → $\sum d_i = 0$.
  • Worst: reversed $(4,3,2,1)$ → $(3,2,1,0)$, $d_i = n - i$ → $\sum d_i = 1 + 2 + \cdots + (n-1) = \frac{n(n-1)}{2}$.
  • Average: hard to reason about with the inversion table; the earlier method is easier.

2.5 Binary Search ★

In one lineSorted data only: look at the middle, throw away half, repeat.Best $O(1)$Worst $O(\log n)$Avg $O(\log n)$

Search for $x$ in a sorted list: look at the middle element; if equal, done; if $x$ is smaller, search the left half, otherwise the right half.

Input:  sorted a[1], a[2], ..., a[n], and x
Output: j if a[j] = x, and 0 if no such j exists

i := 1                     // first entry
m := n                     // last entry
While i ≤ m do
Begin
    j := ⌊(i + m) / 2⌋     // e.g. (1+8)/2 = 4.5 → 4 (round down)
    If x = a[j] then output j and stop
    If x < a[j] then m := j - 1
    else i := j + 1
End
j := 0
output j

Best case: the middle element is the target on the first try → 1 comparison $= O(1)$.
Worst case: $\lfloor \log_2 n \rfloor + 1$ comparisons $= O(\log n)$.
Average case: $O(\log n)$ — derived below (a 10% question on the 113 midterm).

Average-case derivation

Assume $n = 2^k - 1$ (e.g. $k = 4 \Rightarrow n = 15$). Draw the comparisons as a binary tree:

Interactive: the comparison tree (n = 15)

Click any number to see its search path, or a grey box for an unsuccessful search.

  • Successful search: $n$ cases; $2^{i-1}$ of them are found after exactly $i$ comparisons ($i = 1, \dots, k$).
  • Unsuccessful search: $x$ falls into one of the $n + 1$ gaps between elements; each takes $k$ comparisons (down to the bottom of the tree).
  • That is $2n + 1$ cases in total, all assumed equally likely. $k = \log_2(n+1) \approx \log n + 1$ is the number of levels.

平均 = 所有情況的比較次數總和 ÷ 情況數。成功的有 n 種（第 i 層有 2i−1 個、各比 i 次），失敗的有 n+1 種（各比 k 次）。

$$A(n) = \frac{1}{2n+1}\left(\sum_{i=1}^{k} i \cdot 2^{i-1} + k(n+1)\right)$$

Key identity:

$$\sum_{i=1}^{k} i \cdot 2^{i-1} = 2^k(k-1) + 1$$
Proof 1: mathematical induction

$k = 1$: LHS $= 1 \cdot 2^0 = 1$; RHS $= 2^1 \cdot 0 + 1 = 1$. LHS = RHS.

Assume true for $k = m$: $\displaystyle\sum_{i=1}^{m} i\cdot 2^{i-1} = 2^m(m-1) + 1$

Prove for $k = m + 1$ (split off the $(m+1)$-th term):

$$\begin{aligned} \sum_{i=1}^{m+1} i\cdot 2^{i-1} &= \big[2^m(m-1) + 1\big] + (m+1)\cdot 2^m \\ &= 2^m(m - 1 + m + 1) + 1 = 2^m \cdot 2m + 1 = 2^{m+1}\cdot m + 1 \\ &= 2^{m+1}\big((m+1) - 1\big) + 1 = \text{RHS} \qquad \blacksquare \end{aligned}$$
Proof 2: calculus (differentiate the geometric series)
$$\text{Geometric series:}\quad \sum_{i=0}^{k} x^i = \frac{x^{k+1} - 1}{x - 1}$$ $$\begin{aligned} \text{Differentiate both sides:}\quad \sum_{i=1}^{k} i\,x^{i-1} &= \frac{(k+1)x^k(x-1) - (x^{k+1} - 1)}{(x-1)^2} \\ &= \frac{k\,x^{k+1} - (k+1)x^k + 1}{(x-1)^2} \end{aligned}$$ $$\begin{aligned} \text{Substitute } x = 2:\quad &k\cdot 2^{k+1} - (k+1)2^k + 1 \\ = \ &2^k(2k - k - 1) + 1 = 2^k(k-1) + 1 \qquad \blacksquare \end{aligned}$$

技巧：等比級數 Σxi 對 x 微分後，每一項會多出係數 i，正好是我們要的 Σ i·xi−1，最後代 x = 2。

Substitute back ($n + 1 = 2^k$, $2n + 1 = 2^{k+1} - 1$):

$$\begin{aligned} A(n) &= \frac{2^k(k-1) + 1 + k\cdot 2^k}{2n+1} = \frac{2^k(2k-1) + 1}{2^{k+1} - 1} \\ &\approx \frac{2^k(2k-1)}{2^{k+1}} = k - \frac{1}{2} \qquad (n \text{ large} \Rightarrow k \text{ large}) \\ &= O(k) = O(\log n) \end{aligned}$$

Check: $k = 2$ $(n = 3)$: $\frac{4\cdot 3 + 1}{7} = \frac{13}{7} \approx 1.86$, matching a direct count $\frac{(1+2+2) + 4\cdot 2}{7} = \frac{13}{7}$.

2.6 Straight Selection Sort

In one lineFind the minimum, swap it to the front, repeat.Comparisons always $O(n^2)$Avg flag changes $O(n\log n)$

Repeatedly pick the smallest remaining element and swap it into its final position.

7 5 1 4 3   → min is 1, swap with 7  (4 comparisons)
1 5 7 4 3   → min is 3, swap with 5  (3 comparisons)
1 3 7 4 5   → min is 4, swap with 7  (2 comparisons)
1 3 4 7 5   → min is 5, swap with 7  (1 comparison)
1 3 4 5 7   total 10 = n(n−1)/2
For j := 1 to n-1 do
Begin
    f := j                       // not counted
    For k := j+1 to n do
        If a[k] < a[f] then      // comparison
            f := k               // flag change
    a[j] ↔ a[f]
End

Two kinds of operations:

  • Comparison: does not depend on the data; always $(n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2} = O(n^2)$.
  • Flag change (f := k): depends on the data.

Flag change（旗標改變）：每次發現更小的數，就把 f 改成它的位置。只算 f := k，一開始的 f := j 不算。

Average number of flag changes

Let $f(a_1, \dots, a_n)$ = the number of flag changes needed to find the minimum of $a_1, \dots, a_n$.

All 6 permutations for $n = 3$: $f(1,2,3)=0$, $f(1,3,2)=0$, $f(2,1,3)=1$, $f(2,3,1)=1$, $f(3,1,2)=1$, $f(3,2,1)=2$.

Observation:

  1. If $a_n = 1$ (the minimum is last): $f(a_1, \dots, a_n) = 1 + f(a_1, \dots, a_{n-1})$ — the last step must change the flag.
  2. If $a_n \ne 1$: $f(a_1, \dots, a_n) = f(a_1, \dots, a_{n-1})$.

Let $P_n(k)$ = the probability of exactly $k$ flag changes when finding the minimum of $n$ elements. All permutations are equally likely, so the minimum is in the last position with probability $\frac{1}{n}$:

遞迴的意思：最小值 1 有 1/n 的機率在最後一格（會多換一次 flag），有 (n−1)/n 的機率不在最後（次數跟前 n−1 個一樣）。

$$P_n(k) = \frac{1}{n}\,P_{n-1}(k-1) + \frac{n-1}{n}\,P_{n-1}(k)$$ $$\begin{aligned} \text{Initial conditions:}\quad &P_1(0) = 1,\quad P_1(k) = 0 \ \ (k \ne 0) \\ &P_n(k) = 0 \ \text{ if } k \ge n \quad \text{(at most } n-1 \text{ changes)} \end{aligned}$$

$n = 2$: $P_2(0) = \frac12$, $P_2(1) = \frac12$. $n = 3$: $P_3(0) = \frac26$, $P_3(1) = \frac36$, $P_3(2) = \frac16$ (matches the 6 permutations above).

$X_n$ = the average number of flag changes to find the minimum once $= \sum_k k\,P_n(k)$. Substitute the recurrence:

$$\begin{aligned} X_n &= \frac{1}{n}\sum_k k\,P_{n-1}(k-1) + \frac{n-1}{n}\sum_k k\,P_{n-1}(k) \\ &= \frac{1}{n}\big(X_{n-1} + 1\big) + \frac{n-1}{n}\,X_{n-1} = X_{n-1} + \frac{1}{n} \end{aligned}$$ $$X_1 = 0 \ \Rightarrow\ X_n = \frac12 + \frac13 + \cdots + \frac1n = H_n - 1$$

$H_n = 1 + \frac12 + \cdots + \frac1n$ is the $n$-th harmonic number, $H_n \approx \ln n$. Check: $X_2 = \frac12$, $X_3 = 0\cdot\frac26 + 1\cdot\frac36 + 2\cdot\frac16 = \frac56 = H_3 - 1$ ✓. (The textbook proves $X_n = H_n - 1$ by induction: true for $n = 2$; assume for $n = m$; prove for $n = m + 1$.)

Harmonic number（調和數）Hn = 1 + 1/2 + … + 1/n，大約等於 ln n，所以會出現 log。

$A(n)$ = the average number of flag changes for the whole sort. After finding the first minimum, sort the remaining $n - 1$ elements:

$$A(n) = X_n + A(n-1) = \sum_{i=2}^{n}(H_i - 1) = (n+1)H_n - 2n$$ $$H_n \approx \log_e n \ \Rightarrow\ A(n) = O(n\log n)$$

The computer tries all $n!$ orders and counts how many flag changes it takes to find the minimum once.

2.7 Quick Sort ★Quiz 113: best case

In one linePick a pivot, split into smaller | pivot | larger, recurse on both sides.Best $O(n\log n)$Worst $O(n^2)$Avg $O(n\log n)$

Divide-and-conquer: use the first element $X$ as the pivot, move smaller elements to its left and larger ones to its right, then recursively sort both sides.

Divide-and-conquer（各個擊破）：把問題切成小問題、分別解決，再合併結果。

Implementation with two pointers $i, j$

  1. $X :=$ the first element. $i$ points to the front, $j$ to the back.
  2. Move $j$ leftward until it finds an element $\lt X$; swap it with $a_i$.
  3. Move $i$ rightward until it finds an element $\gt X$; swap it with $a_j$.
  4. Repeat until $i \ge j$. Now $X$ is in its final position; one scan costs $O(n)$.
  5. Recurse on QuickSort(f, j-1) and QuickSort(j+1, l).
QuickSort(f, l)
    If f ≥ l then Return
    X := a[f]                  // pivot = first element
    i := f
    j := l
    While i < j do
    Begin
        While a[j] ≥ X and i < j do j := j - 1
        a[i] ↔ a[j]
        While a[i] ≤ X and i < j do i := i + 1
        a[i] ↔ a[j]
    End
    QuickSort(f, j - 1)
    QuickSort(j + 1, l)

(The slides' inner loops omit i < j; a real implementation needs it, or the pointers run past each other.)

Interactive: the first partition (slide example 3 6 1 4 5 2)

Result 2 1 3 4 5 6: 3 is in its final position; everything on its left (2, 1) is smaller and everything on its right (4, 5, 6) is larger. Then recurse on each side.

Best case: $O(n\log n)$

Every split produces two halves of about equal size (the pivot happens to be the median).

$$\begin{aligned} T(n) &= 2T(n/2) + cn \\ &= 2\big[2T(n/4) + cn/2\big] + cn = 4T(n/4) + 2cn \\ &= 8T(n/8) + 3cn = \cdots \\ &= 2^k\,T(n/2^k) + k\cdot cn \end{aligned}$$ $$\text{Let } n = 2^k\ (k = \log_2 n):\quad T(n) = n\,T(1) + cn\log_2 n = O(n\log n)$$

$cn$ = the scan / comparisons done in one round.

Intuition: sizes go $n \to n/2 \to n/4 \cdots$, so there are $\log n$ rounds, and each round makes about $n$ comparisons in total (e.g. round 2: $\frac{n}{2}\cdot 2 = n$). Hence $n\log n$.

直覺：每次切一半，切 log n 層；每一層加起來大約比 n 次，所以是 n log n。

Worst case: $O(n^2)$

The pivot is always the smallest or the largest element, e.g. already sorted 1 2 3 4 5. Each round removes only one element:

$$(n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2} = O(n^2)$$
See it: best case vs. worst case, level by level

Each row is one level of recursion. Its total width is the work done on that level (≈ n comparisons).

Best: pivot splits in half
Worst: pivot is the smallest (sorted input)
Classic mistake from Quiz 113“Already sorted 1 2 3 4 is the best case, $O(n)$” → completely wrong. Sorted input is quick sort's worst case. $O(n)$ is insertion sort's best case — don't mix them up.

已排好的資料：對 insertion sort 是最好（O(n)），對 quick sort 是最差（O(n²)）。

Average case: $O(n\log n)$

Suppose a split produces parts of size $s$ and $n - s$, with $s = 1, \dots, n$ equally likely (probability $\frac1n$):

$$\begin{aligned} T(n) &= \operatorname*{Avg}_{1 \le s \le n}\big[T(s) + T(n-s)\big] + cn \\ &= \frac{1}{n}\sum_{s=1}^{n}\big[T(s) + T(n-s)\big] + cn, \qquad T(0) = 0 \end{aligned}$$

整體策略：先乘 n、再用「n 代 n−1」寫出另一式，兩式相減消掉長長的 Σ，得到簡單的遞迴，最後展開成調和數 Hn。

Step 1: multiply both sides by $n$ and expand the sum ($T(1), \dots, T(n-1)$ each appear twice, $T(n)$ once):

$$nT(n) = 2T(1) + 2T(2) + \cdots + 2T(n-1) + T(n) + cn^2$$ $$(n-1)T(n) = 2T(1) + 2T(2) + \cdots + 2T(n-1) + cn^2 \qquad (1)$$

Step 2: replace $n$ by $n - 1$:

$$(n-2)T(n-1) = 2T(1) + \cdots + 2T(n-2) + c(n-1)^2 \qquad (2)$$

Step 3: $(1) - (2)$, using $n^2 - (n-1)^2 = 2n - 1$:

$$(n-1)T(n) - (n-2)T(n-1) = 2T(n-1) + c(2n-1)$$ $$(n-1)T(n) = nT(n-1) + c(2n-1)$$

Step 4: divide both sides by $n(n-1)$ and use $\frac{2n-1}{n(n-1)} = \frac1n + \frac{1}{n-1}$:

$$\frac{T(n)}{n} = \frac{T(n-1)}{n-1} + c\left(\frac1n + \frac{1}{n-1}\right)$$

Step 5: unroll down to $\frac{T(1)}{1}$ (take $T(1) = 0$):

$$\begin{aligned} \frac{T(n)}{n} &= c\left(\frac1n + \frac1{n-1}\right) + c\left(\frac1{n-1} + \frac1{n-2}\right) + \cdots + c\left(\frac12 + \frac11\right) \\ &= c(H_n - 1) + cH_{n-1} \\ &\approx 2cH_n \end{aligned}$$ $$T(n) \approx 2cn\,H_n \approx 2cn\log_e n = O(n\log n)$$

Why $c(H_n - 1) + cH_{n-1}$: every fraction except $\tfrac1n$ and $1$ appears twice in the sum.

Summary: Quick Sort Best $O(n\log n)$, average $O(n\log n)$, worst $O(n^2)$. Compare: heap sort's worst case is $O(n\log n)$.

2.8 Finding Ranks: 2-D Ranking ★Quiz 114

In one lineSplit by the median $x$, solve each half, then fix the right half by counting $y$ values.Brute force $O(n^2)$Divide & conquer $O(n\log^2 n)$

1-D domination

$a_i$ dominates $a_j$ if $a_i \gt a_j$. The rank of $a_i$ = the number of elements dominated by $a_i$.
Example: 3, 5, 1, 7 → rank(1)=0, rank(3)=1, rank(5)=2, rank(7)=3. Method: sort; the position is the rank. $O(n\log n)$.

2-D domination

$$A = (a_1, a_2) \text{ dominates } B = (b_1, b_2) \iff a_1 \gt b_1 \ \textbf{and}\ a_2 \gt b_2$$ $$\operatorname{rank}(x) = \#\text{ points in } S \text{ dominated by } x$$

Dominate（支配）：x 和 y 兩個座標都要比對方大才算。只有一個大的話叫 incomparable（無法比較）。

Some pairs are incomparable (e.g. one has larger $x$ but smaller $y$). The problem: find the rank of every point.

Straightforward method: compare every point with every other point: $O(n)$ per point, $n$ points → $O(n^2)$.

Interactive: click a point to see what it dominates

The shaded box is the “lower-left” region. Every point inside it is dominated, so rank = how many points are in the box.

Divide-and-conquer algorithm

  1. Step 1: find a vertical median line $L$ (the median of the $x$ values) that splits the points into a left half $A$ and a right half $B$ of equal size.
  2. Step 2: recursively find the ranks of the points in $A$ and the ranks of the points in $B$.
  3. Step 3: sort the points of $A \cup B$ by $y$ value and scan from bottom to top; add to each point in $B$ “the number of points in $A$ with a smaller $y$”. (Ranks in $A$ do not change: every point in $A$ has a smaller $x$ than every point in $B$, so it cannot dominate any point in $B$.)

Why is Step 3 correct? Every point in $B$ has a larger $x$ than every point in $A$, so a point $p \in B$ dominates $q \in A$ $\iff p.y \gt q.y$. Counting $y$ values is enough.

為什麼只要比 y：右半 B 的 x 一定比左半 A 大，所以只剩 y 要比。左半 A 的 rank 不用改，因為它們的 x 比較小，不可能支配右邊的點。

Worked example

8 points: A(1,3), B(2,6), C(3,1), D(4,5) | E(5,2), F(6,7), G(7,4), H(8,8). $L$ is at $x = 4.5$.

Time complexity derivation

  • Step 1: find the median. The intuitive way sorts first, $O(n\log n)$, then takes the $n/2$-th element, $O(1)$ → $O(n\log n)$. (Chapter 6 shows an $O(n)$ method.)
  • Step 2: $2T(n/2)$.
  • Step 3: sort by $y$, $O(n\log n)$, plus one left-to-right scan to update ranks, $O(n)$ → $O(n\log n)$.
$$\begin{aligned} T(n) &\le 2T(n/2) + c\,n\log n \qquad (n \gt 1) \\ &= 2\big[2T(n/4) + c\tfrac{n}{2}\log\tfrac{n}{2}\big] + cn\log n \\ &= 4T(n/4) + cn\log\tfrac{n}{2} + cn\log n \\ &= 8T(n/8) + cn\log\tfrac{n}{4} + cn\log\tfrac{n}{2} + cn\log n \\ &\ \ \vdots \\ &= n\,T(1) + cn\Big[\log n + \log\tfrac{n}{2} + \log\tfrac{n}{4} + \cdots + \log 2\Big] \\ &= n\,T(1) + cn\Big[\log n + (\log n - 1) + (\log n - 2) + \cdots + 1\Big] \\ &= n\,T(1) + cn\cdot\frac{\log n\,(\log n + 1)}{2} \\ &= O(n\log^2 n) \end{aligned}$$

The bracket has $\log n$ terms, and $\log\tfrac{n}{2^i} = \log n - i$, so it is an arithmetic series.

Small reminderThe bracket is an arithmetic series (terms differ by 1), not a geometric one. The 114 paper called it geometric; the answer was right but the term was wrong.

中括號裡是「等差級數」（每項差 1），不是等比級數。等差級數和 = 項數 × (首項 + 末項) ÷ 2。

Both the worst case and the average case are $O(n\log^2 n)$ — much better than the $O(n^2)$ exhaustive search.

2.9 How hard is a problem? Lower bound, Ω, Θ

In one lineΩ = the least time any algorithm needs (a property of the problem). If an algorithm matches it, the algorithm is optimal.

The lower bound of a problem is the least time complexity required by any algorithm that solves it. There are worst-case lower bounds and average-case lower bounds.

Lower bound（下界）是「問題」的性質：不管用什麼演算法，至少都要花這麼多時間。Big-O 則是描述「某個演算法」最多花多少時間。

$$\begin{aligned} f(n) = \Omega(g(n)) &\iff \exists\, c, n_0 \gt 0:\ |f(n)| \ge c\,|g(n)| \ \ \forall n \ge n_0 \\ f(n) = \Theta(g(n)) &\iff \exists\, c_1, c_2, n_0 \gt 0:\ c_1|g(n)| \le |f(n)| \le c_2|g(n)| \ \ \forall n \ge n_0 \end{aligned}$$

Example: $f(n) = 3n^2 + 2 = \Omega(n^2)$, and also $= \Omega(n)$ (Ω is not unique; we normally give the largest one); $3n^2 + 2 = \Theta(n^2)$ (both at least and at most, i.e. exact).

NotationMeaningWe usually give
$O(\,)$at most (upper bound)the smallest $g(n)$
$\Omega(\,)$at least (lower bound)the largest $g(n)$
$\Theta(\,)$exact—

Example: sorting

$\Omega(1)$, $\Omega(n)$, and $\Omega(n\log n)$ are all lower bounds for sorting (not unique).

  • $\Omega(1)$: obvious (trivial) — you must read at least one item.
  • $\Omega(n)$: you must look at all $n$ elements (trivial).
  • $\Omega(n\log n)$: proven in a later chapter.
  • Is $\Omega(n^2)$ a lower bound? No! A lower bound is the least time any algorithm needs, and heap sort's worst case is already $O(n\log n)$, so the true lower bound is $\le n\log n$. (You cannot argue from quick sort's $O(n^2)$ worst case.)

How do we get a lower bound? We cannot try every algorithm, so it must be proven theoretically: find one, then try to raise it.

Common traps (read this 5 minutes before the quiz)

  1. Already-sorted input is quick sort's worst case, $O(n^2)$ — not the best case.
  2. Already-sorted input is insertion sort's best case, $O(n)$, with $n - 1$ comparisons.
  3. Convex hull, MST, and 1-center are polynomial; knapsack, TSP, partition, and art gallery are NP-complete.
  4. NP-complete ≠ “proven exponential”. A problem proven to need exponential time is an exponential problem (e.g. printing all permutations).
  5. In a Big-O derivation, always state $c$ and $n_0$; when $\log n$ appears, use $n_0 = 2$.
  6. In the inversion table, $d_j$ counts larger elements to the left of the number $j$, not of position $j$.
  7. Selection sort's comparisons are always $O(n^2)$; only the average number of flag changes is $O(n\log n)$. f := j is not a flag change.
  8. In 2-D ranking, Step 3 updates only the ranks in the right half $B$; expanding $T(n)$ gives an arithmetic series → $O(n\log^2 n)$.
  9. Binary search requires sorted data; there are $n + 1$ unsuccessful cases, each taking $k$ comparisons.
  10. Difficulty of analysis: best (easiest) < worst < average (hardest).

Mock quiz B

1. (2%) What is the Partition Problem? Give an example. Which class does it belong to?

Given a set $S$ of positive integers, split it into $S_1$, $S_2$ ($S_1 \cap S_2 = \varnothing$, $S_1 \cup S_2 = S$) with equal sums. Example: $S = \{1,7,10,4,6,8,3,13\}$, $S_1 = \{1,10,4,8,3\}$, $S_2 = \{7,6,13\}$, both sum to 26. NP-complete.

2. (2%) Analyze the average case of Straight Insertion Sort by data movement. Show the derivation.

$M = \sum_{j=2}^{n}(2 + d_j)$, where $d_j$ = the number of larger elements to the left of $x_j$. The rank of $x_j$ among the first $j$ elements is uniform (probability $\frac1j$ each), so $d_j \in \{0, \dots, j-1\}$ ⇒ $E[d_j] = \frac{j-1}{2}$.

$$M = 2(n-1) + \sum_{j=2}^{n}\frac{j-1}{2} = 2(n-1) + \frac{n(n-1)}{4} = O(n^2)$$
3. (2%) What is the average-case time complexity of binary search? Show the derivation.

Let $n = 2^k - 1$. Successful: $2^{i-1}$ elements need $i$ comparisons; unsuccessful: $n + 1$ cases with $k$ comparisons each. Prove by induction that $\sum_{i=1}^{k} i\cdot 2^{i-1} = 2^k(k-1) + 1$:

$$A(n) = \frac{\sum_{i=1}^{k} i\cdot 2^{i-1} + k(n+1)}{2n+1} = \frac{2^k(2k-1) + 1}{2^{k+1} - 1} \approx k - \frac12 = O(\log n)$$
4. (2%) What are the best / worst / average numbers of flag changes in straight selection sort? Outline the average-case derivation.

Best $O(1)$, worst $O(n^2)$, average $O(n\log n)$.

$$P_n(k) = \tfrac{1}{n}P_{n-1}(k-1) + \tfrac{n-1}{n}P_{n-1}(k)$$ $$\Rightarrow\ X_n = X_{n-1} + \tfrac1n \ \Rightarrow\ X_n = H_n - 1$$ $$A(n) = X_n + A(n-1) = \sum_{i=2}^{n}(H_i - 1) = (n+1)H_n - 2n$$ $$H_n \approx \ln n \ \Rightarrow\ A(n) = O(n\log n)$$

Quick true / false (useful for the midterm too)

(a) Quick sort is optimal in the average case.

True. Its average $O(n\log n)$ equals sorting's lower bound $\Omega(n\log n)$.

(b) Insertion sort needs $(n-1)$ comparisons in the best case.

True. On sorted input each element needs only one comparison.

(c) The convex hull problem is NP-complete.

False. Divide-and-conquer solves it in polynomial time ($O(n\log n)$).

(d) $\Omega(n^2)$ can be a lower bound for sorting.

False. Heap sort's worst case is $O(n\log n)$, so the lower bound cannot exceed that.

(e) A problem has lower bound $\Omega(n\log n)$, and someone claims an $O(n)$ algorithm for it.

Impossible (Case 3: an error).

(f) The 1-center problem is NP-complete.

False. It can be solved in $O(n)$.
